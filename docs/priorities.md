## 2. 捨てるもの（捨ててよいと決定済み）
| 捨てるもの | 理由 |

## 3. 短期の「完成」の定義
- [ ] 災害統計を正解に、NASA の入力だけでリスクモデルが動く（`analyze_disasters.py`）
- [ ] 雨だけ・風だけ・雨×風を、年単位の交差検証で比べた結果が出ている（★数字）
- [ ] 予報（GEOS-FP）を入れて、「この予報なら危険度はいくつか」が出る
- [ ] 品種を選ぶと閾値が変わる
- [ ] 限界を言える: 正解は風水害の合計で倒伏だけではない、早刈りのバイアス、予報誤差は未検証

## 4. 公式 Objectives との対応（正直な評価）
公式の Objectives は「NASA の地球観測と地域の農業情報を組み合わせ、**輪作の選択肢**を探る意思決定支援ツール（3 つ以上の輪作戦略の比較）」。我々の短期の成果は輪作そのものではないので、**対応は部分的**。審査の Relevance（課題との関連）で弱くなりうる。★チーム登録のチャレンジ名（`TEAM.md` は Trend Detective）と、この Objectives が同じチャレンジのものか、会場で確認する。

| Objectives の要素 | 我々の対応 | 強さ |
|---|---|---|
| NASA の地球観測と地域の農業情報の組み合わせ | GEOS-FP、IMERG、POWER、SMAP、HLS＋農水省統計、品種、友人のヒアリング | 強い |
| 使ってよい NASA データ（GPM、POWER、SMAP、Landsat 系＝HLS、SRTM） | 使う予定のもの（IMERG は GPM、POWER、SMAP、HLS）は一致 | 強い |
| 極端な降水、土壌水分、気象の変化への強さ（resilience） | 大雨と土壌水分を入力にした、倒伏リスクの予測 | 中 |
| 現在の作物が、どの季節に弱いか（vulnerable seasons） | 出穂後積算気温で見た、倒れやすい時期（400〜1,500℃）の特定 | 中 |
| 意思決定支援であり、農家の判断や地域の専門知識を置き換えない | 「判断するのは農家。材料を並べる」。品種を選べる | 強い |
| 情報の欠け（information gaps）とリスクを明示する | 限界を先に言う姿勢（正解データ、早刈り、予報誤差） | 強い |
| 3 つ以上の輪作戦略の比較（既存を含む） | 未実装。展望（下） | 弱い |
| 土の健康、窒素固定、市場性など | 扱わない | 弱い |

### 展望: 履歴から作付け計画へ（無理なく結びつける道筋）
1. 倒伏の危険度を、年ごと・地域ごと・品種ごとに**履歴として蓄積**する（過去 25 年を同じモデルで再計算できる）
2. その履歴から、「この品種・この作期は、過去にどれだけ危険な年が何回あったか」が分かる
3. すると、**品種と作期（出穂時期）の組み合わせ**を、既存のやり方を含む 3 通り以上で比べられる（例: 既存＝コシヒカリの通常期、背の低い品種、作期をずらして出穂を台風のピークから外す）
4. さらに、輪作（稲以外の作物を挟む）まで広げれば、Objectives の本題に届く
- 言い方: 「今回は、その土台になる倒伏リスクの予測を作りました。履歴を蓄積すれば、作付け計画の比較に広げられます」
- 注意: これは展望であって、今回は作らない・検証もしていない。そう言う
