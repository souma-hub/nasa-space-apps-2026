# 解析とモデルの報告（茨城・千葉 → 全国 → 統一モデル → デモ）

最終更新: 2026-11-14 深夜。数字の出典は `results/` の各レポート。ストーリーの正は `docs/story.md`。

## 1. 茨城・千葉モデル（出発点）
- データ: 2004〜2021 年 8〜9 月に関東南部から 300 km 以内に来た台風 23 個。正解は農水省の災害統計（茨城＋千葉の水稲被害 100 ha 以上＝被害あり 7 個）。
- 解析（被害あり vs なし）: 雨（NASA IMERG）p=0.003、地上の最大瞬間風速 p=0.001。NASA の風（POWER）は p=0.30 で効かない。実り具合（出穂後積算気温）は p=0.11 で境界。
- 予測（台風を 1 つずつ抜く）: 規則「雨 30 mm かつ出穂後 400℃」で見逃し 1/7、被害なし 16 個のうち 8 個で「待ってよい」。並べ替え検定 p=0.06（境界）。
- 実り具合を入れた理由: 茨城・千葉は主な品種（コシヒカリ、ふくまる、あきたこまち、にじのきらめき）と作付け時期の前提が、ヒアリングと県の資料にある。

## 2. 全国への一般化（同じ手順を全国に当てる）
- データ: 都道府県 × 台風 1,815 行（台風 86 個、47 都道府県、被害あり 271 行）。`results/japan_report.txt`
- 解析: 雨 p≈10⁻⁶⁶、NASA の風 p≈10⁻⁶⁷。
- 予測（台風を 1 つずつ抜く）: 雨だけ AUC 0.82 → 雨＋風 AUC 0.88（95% 区間 0.84〜0.91、偶然の 0.5 から大きく離れる）。勾配ブースティングでも 0.88 で、軽いロジスティック回帰で十分。
- 茨城・千葉との違い:
  - 風: 全国では効く。台風との距離の代わりではない（距離を入れた上でも風は有意に効き、距離は風の代わりにならない。`results/japan_wind_report.txt`）。関東で効かなかったのは、約 50 km の格子では小さく強い台風の突風を捉えきれないためと考える。
  - 実り具合: 全国では外した。地域ごとに品種・作付け時期の前提が違い、5/1 からの積算温度という粗い代わりでは表せない（入れても効かない）。
- 場所の変数（`results/japan_location_report.txt`）: 緯度経度は効かない（沖縄を見分けていただけ）。都道府県の補正は確率の当たり方を改善（AUC 0.876 → 0.897、Brier も有意に改善）。県の差は座標ではなく、田の広さ・栽培・NASA の風の出方などの違いと考える（未分離）。

## 3. 統一モデル（`unified_model.py`、`lodging_unified.py`、`results/unified_model.json`）
「手法を一般化する」と言える形に、1 つの式にまとめた。

```
logit P = 全国の部分［雨 ＋ 風 ＋ 都道府県の補正］      ← 全国のデータで学習
        ＋ 地域の追加項［d ＋ e·実り具合の時期］          ← 前提（品種・作付け時期）がある地域だけ
```
- 地域の追加項は、全国の部分を固定して、その地域のデータで 2 係数だけ学習する（茨城・千葉: e=+0.65。「青いうちは倒れない」と同じ向き）。
- 他の地域も、地元の知見（品種・作付け時期・農家のヒアリング）があれば、同じ形で追加項を足せる。
- 茨城・千葉の台風 23 個での検証（1 つ抜き。抜いた台風は全国の学習からも外す。`results/unified_kanto_loo.csv`）:

| | 見逃し | 待ってよい | Fisher 片側 |
|---|---|---|---|
| 茨城・千葉の規則 | 1/7（2013 年 18 号、338 ha） | 8/16 | p=0.12 |
| 統一モデル | 1/7（2019 年 15 号、7,860 ha） | 10/16 | p=0.045 |

- **限界（正直に書く）**: 統一モデルは 2019 年 15 号（房総半島台風、千葉の倒伏の実例）を見逃した。小さく強い台風で、NASA の風が 6.9 m/s と弱く出たため。学習する台風が増えれば改善する可能性がある。
- 動作要件: 実行時は numpy だけ、1 回の判断は 0.1 ms 未満。4 コア CPU で十分。

## 4. デモ
- 架空の入力: `uv run demo_lodging.py`（9 つのシナリオ）、または `uv run demo_lodging.py --pref 茨城 --past 15 --forecast 25 --wind 12 --gdd 900`
  - 例: 同じ中くらいの台風でも、稲が実っていれば「刈る」（27%）、まだ実りきっていなければ「待ってよい」（16%）。倒れにくい品種なら「待ってよい」（14%）。
  - 強い台風なら、稲が実りきっていなくても「刈る」（79%）。安全側に倒す方針どおり。
- 実データ: `uv run predict_lodging.py --pref 千葉 --replay 2019-09-09`（過去の台風の再現）、`uv run predict_lodging.py`（GEOS-FP の最新予報で判断。動作確認済み）

## 5. 結論と展望
- 茨城・千葉で作った手順（被害統計を正解にする → NASA のデータで検定する → 台風単位の交差検証で変数を選ぶ → 軽いモデルにする）は、全国でもそのまま使え、全国では予測も明確に有意になった。
- この手順に必要なのは、**世界中で同じ形で手に入る NASA のデータ**（IMERG の雨、POWER・GEOS-FP の風と気温）と、**その地域の被害の記録**、あれば**地元の知見**の 3 つだけ。
- したがって、同じ手法で、**他の農作物（麦・大豆・果樹などの風雨の被害）や、他の国・地域でも、同様に予測できる可能性**がある。被害の記録がある地域なら、全国の部分を学習し、地元の知見を地域の追加項として足していける。
- 予測と結果の履歴をためれば、地域の追加項が育ち、作付計画（品種・田植え日・輪作）の判断支援へ広げられる（Field Shift とのつながり）。
- 注意: 他の作物・地域への適用は「可能性の提示」であり、まだ検証していない。
